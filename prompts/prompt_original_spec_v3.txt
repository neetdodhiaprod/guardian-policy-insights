═══════════════════════════════════════════════════════════════
CRITICAL RULES - READ FIRST
═══════════════════════════════════════════════════════════════

BEFORE you categorize ANY feature, check these rules:

1. PED WAITING PERIOD:
- 12 months = GREAT
- 24 months = GOOD
- 36 months = GOOD (this is 3 years - STILL GOOD, NOT a red flag)
- 48 months = GOOD (this is 4 years - STILL GOOD, NOT a red flag)
- 60+ months = BAD (only flag if MORE than 48 months)

2. SPECIFIC ILLNESS WAITING:
- 12 months = GREAT
- 24 months = GOOD (standard)
- 36+ months = BAD (only flag if MORE than 24 months)

3. ROOM RENT:
- "At Actuals" / "Any room" / "No limit" / "No capping" = GREAT
- "Single Private AC room" / "Single AC" = GOOD (NOT great)
- Any rupee cap (₹3,000/day, ₹5,000/day, etc.) = BAD

ROOM RENT RULE — STRICT:
- Categorize room rent EXACTLY ONCE based on the DEFAULT term stated.
- "At Actuals" is unambiguous — it means GREAT. Do NOT also put it in GOOD or UNCLEAR.
- If some sub-plans have different room limits, mention it briefly in the explanation only.
- NEVER place the same room rent feature in multiple categories.

6. BUILT-IN ADDITIONAL SI BUFFER (Secure Benefit / Super NCB / Enhanced SI / any equivalent):
- If the policy offers ANY feature that provides extra Sum Insured activating after base SI is exhausted = GREAT.
- The PRESENCE of this feature qualifies as GREAT.
- The exact amount being schedule-dependent does NOT downgrade it to GOOD.
- Note the schedule-dependency briefly in the explanation only. Do NOT put it in GOOD because of this.

4. INITIAL WAITING:
- 0 days = GREAT
- 30 days = GOOD (standard)
- 31+ days = BAD

5. STANDARD EXCLUSIONS - NEVER FLAG:
- Maternity (in base plan) = IGNORE
- Infertility = IGNORE
- Cosmetic surgery = IGNORE
- All other standard IRDAI exclusions = IGNORE

═══════════════════════════════════════════════════════════════
OPTIONAL COVERS / ADD-ONS - IMPORTANT DISTINCTION
═══════════════════════════════════════════════════════════════

Many policies offer OPTIONAL covers where customers make a conscious trade-off.
These are NOT red flags - they are CHOICES that provide flexibility.

RULE: If a restriction ONLY applies when customer OPTS INTO a discounted/optional cover, it is NOT a red flag.

HOW TO IDENTIFY OPTIONAL VS MANDATORY:

OPTIONAL (flag as GOOD or don't flag):
- "If the Insured Person has opted for this Optional Cover..."
- "Subject to the Insured Person choosing..."
- "Available as an add-on..."
- "Discount available if you choose..."
- Customer must actively select it

MANDATORY (may be RED FLAG):
- "Applicable on all claims..."
- "Co-payment shall be deducted..."
- "In all cases, the insured shall bear..."
- No opt-out mentioned
- Applies by default to all policyholders

═══════════════════════════════════════════════════════════════
🟡 NEEDS CLARIFICATION
═══════════════════════════════════════════════════════════════

ONLY flag when GENUINELY unclear:
- "As per company discretion" without criteria
- Benefit mentioned but no limit specified
- Conflicting statements
- Vague terms: "reasonable", "customary", "as decided by TPA"

DO NOT flag:
- Plan variants / sub-plans within the same policy wording document. Analyze and categorize based on the DEFAULT / PRIMARY terms stated in the document. If a feature has sub-plan variations, state the default in the category and briefly note the variation in the explanation field only. NEVER put "varies by plan" or "check your schedule" items in needs clarification.
- Features explicitly marked as "Not Covered" or "Not Applicable" for the primary plan — omit them.
- Co-pay is ALWAYS reported. If explicitly stated as 0% / "no co-pay" = GREAT. If co-pay simply not mentioned anywhere = UNCLEAR ("Co-pay terms not explicitly stated in policy wording — verify with insurer or policy schedule"). Do not infer absence as GREAT.
