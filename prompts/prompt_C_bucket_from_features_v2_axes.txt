You are grading extracted policy features into GREAT / GOOD / BAD (RED FLAG) / UNCLEAR.

INPUT:
You will receive a JSON array of feature objects extracted from a single policy wording. Each object has:
- clause_id (number)
- page (number)
- type (string)
- name (string)
- quote (string, verbatim from the policy wording)
- reference (string|null)
- notes (string|undefined)

You must base decisions ONLY on the provided quotes. Do not invent facts, limits, or references.

BUCKETING LOGIC (use the 3-axis rubric internally):

Step 0 — Evaluable?
- If the feature depends on Policy Schedule / plan variant / annexure not provided, or is too vague to assess -> UNCLEAR.

Step 1 — Classify the feature:
- Upside (benefit/coverage/extension)
- Downside (exclusion/cap/sublimit/deductible/copay/proportionate deduction/harsh condition)
- Neutral/process/definition (may become downside if it introduces a restriction)

Step 2 — Score each feature 0–2 on:
A) Magnitude: 2 big money/coverage impact; 1 moderate; 0 low.
B) Likelihood: 2 common claims/behavior; 1 occasional; 0 rare.
C) Friction/Traps: 2 denial/reduction shock; 1 some hoops; 0 straightforward.

Step 3 — Map to buckets:
- BAD (RED FLAG): if Downside and (Trap=2) OR (Magnitude=2 and Likelihood>=1) OR it is a known claim-shock mechanic (e.g., proportionate deduction).
- GREAT: if Upside and Magnitude=2 and Trap<=1 and terms are explicit.
- GOOD: evaluable but not exceptional; standard; or mild downside (Magnitude=1, Trap<=1) clearly disclosed.
- UNCLEAR: as per Step 0.

SELECTION / DEDUPE:
- Many inputs are duplicates (esp. definitions). Choose high-signal items.
- Output at most 15 items per bucket.
- Prefer concrete mechanics: room rent / ICU / proportionate deduction, waiting periods, restore/recharge, non-payables/consumables, deductibles/copays, major exclusions, pre/post windows.

OUTPUT (STRICT JSON):
Return a single JSON object with exactly these keys: GREAT, GOOD, BAD, UNCLEAR, disclaimer.
Each bucket value is an array of objects with exactly: name, quote, reference, explanation.

Rules:
- quote MUST be copied verbatim from an input feature.quote.
- reference MUST be input feature.reference if present; else "Not provided".
- explanation must be 1–2 sentences and MUST include:
  (a) Impact sentence (how it affects payout/OOP/usability), and
  (b) Trigger condition (when it applies), if applicable.

Disclaimer (exact string):
"Disclaimer: This analysis is for informational purposes only and does not constitute financial or insurance advice. Always read your policy documents carefully and consult with a licensed insurance advisor for specific guidance."

Now grade the provided features.
